# AI 助手 · 设计方案 v1.1

> 轻量团队消息同步工具。单进程 Node 服务 + 纯 HTTP 轮询（3 秒），零第三方依赖，无 WebSocket。
> 本期实现「消息同步」与「系统设置」，导航栏预留后续菜单。

**已确认的设定**：需要密码登录 · 轮询 3 秒 · 首屏只取最近 3 条 · 显示条数可调 · 系统设置里可改用户名和密码 · HTTPS 由部署方自行在反向代理层处理。

---

## 1. 设计目标

| 维度 | 要求 | 实现方式 |
|---|---|---|
| 交互 | 同一界面发消息，其他登录用户 3 秒内看到 | 3s 增量轮询（`afterId` 游标），发送后立即本地回显 |
| 容量 | 界面只显示最新 50 条 | 首屏取 3 条，后续增量追加，DOM 超过 50 条即裁剪 |
| 存储 | 最多保留 30 天、最多 10000 条 | 写入后双条件修剪（先按时间、再按条数） |
| 身份 | 用户名 = 登录用户名 + 本机设备名 | `displayName = 用户名 · 设备名`，同账号多设备=多个在线位 |
| 并发 | 最多 20 个在线用户（按设备计） | 会话表 + 5s 心跳，15s 无心跳回收，满载拒绝新登录 |
| 安全 | 需要密码 | scrypt + 随机盐哈希，账号存在服务端 |
| 风格 | 简约大气 | 无阴影、单一强调色、0.5px 细线分隔、200px 窄导航 |

---

## 2. 信息架构

```
AI 助手
├─ 消息同步   ← 默认首页
└─ 系统设置   ← 账号 / 显示 / 设备与连接 / 数据 / 关于
   └─ （后续：知识库 / 任务 / 成员 …预留位置）
```

**布局**：左侧导航 200px 固定，右侧内容区自适应；窗口 < 860px 时导航收成 64px 图标条。

### 2.1 导航栏
- 顶部：Logo 方块（30px，圆角 8）+「AI 助手」
- 菜单项：图标 + 文字，圆角 8，激活态强调色浅底 + 强调色文字 + 500 字重
- 底部固定：当前用户卡片（首字头像 + 用户名 + 设备名 + 连接状态）

### 2.2 消息同步页
- **顶部栏**（58px）：`# 公共频道` + 副标题「全体在线成员可见 · 首屏加载最近 3 条」；右侧在线人数胶囊 `● 3 / 20`
- **消息区**：底部对齐（消息少时贴着输入框），自己发的头像用强调色浅底。每行：头像、用户名、设备名胶囊、时间、正文
- **复制按钮**：每条消息右侧 26×26 图标，默认 35% 透明度，悬停该行升到 100%，点击后变对勾 1.2s 并提示「已复制」
- **输入区**：圆角输入框（随内容自动增高至 132px）+ 发送按钮；底部提示 `Enter 发送 · Shift + Enter 换行` 与字数计数
- **新消息浮标**：用户上滑查看时不打断，只在底部浮出「有新消息」

### 2.3 系统设置页
卡片式分组：
1. **账号**：用户名、当前密码（验证用）、新密码、确认新密码 → 保存后强制重新登录
2. **显示**：消息显示条数 20 / 50 / 100（默认 50）
3. **设备与连接**：设备名（下次登录生效）、服务器地址、刷新间隔（3 秒，只读）
4. **数据**：清空本地偏好、退出登录
5. **关于**：版本、保留策略、在线设备数

## 4. 登录与身份

1. 未登录显示居中登录卡（380px）：登录 / 创建账号两个 tab。
   - 登录：用户名、密码、设备名
   - 创建账号：用户名、密码（设备名首次进入后自动补齐）
2. 用户名 2-16 位（中文 / 字母 / 数字 / 下划线 / 短横线），密码 6-32 位。
3. 设备名：首次访问按 UA 推断填入（`Windows-Chrome`、`Mac-Browser` 等），可改，存 `localStorage`。
4. 密码：`scrypt(password, 随机16字节盐, 32字节)` 存哈希，登录用 `timingSafeEqual` 比对。
5. 身份标识：
   - `deviceKey = 用户名#设备名`（同账号同设备重复登录复用同一身份，不额外占位）
   - `displayName = 用户名 · 设备名`（界面展示）
   - `sessionId` 每次登录新生成，仅用于在线计数与心跳
6. 会话存 `localStorage`，同一浏览器多标签页共用一份，不会重复占位。
7. 默认创建 `admin / admin123`，登录后提示到设置里修改。
8. 账号改动（改用户名或密码）后，该账号所有会话立即失效 → 前端跳回登录页。

## 5. 在线人数与并发

- 在线上限 **20**，单位是「会话（设备）」：同账号两台设备 = 2。
- 登录校验：若该设备已有活跃会话 → 直接替换；否则 `活跃数 >= 20` 时返回 `409 ROOM_FULL`。
- 心跳 `POST /api/heartbeat` 每 **5s**；15s 未收到即判定离线（关标签页、断网、休眠都能自然回收）。
- 页面隐藏时暂停轮询、心跳继续；恢复可见立即补拉一次。
- 页面关闭用 `navigator.sendBeacon('/api/logout?sid=…')` 立即释放名额。
- 在线名单只下发 `displayName` 与最近活跃时间，不下发 IP。

## 6. 消息规则

### 6.1 显示
- **新会话首屏只拉最近 3 条**：`GET /api/messages?limit=3`（升序返回，直接渲染）。
- 之后每 3 秒 `GET /api/messages?afterId=<游标>&limit=<显示条数>` 增量拉取。
- 前端数组上限 = 显示条数（默认 50，可调 20/100），超出从头裁掉。
- 滚动停在底部则自动跟随；上滑查看时只出「有新消息」浮标。

### 6.2 保留（服务端）
每条消息写入后执行修剪：
1. 删除 `createdAt < now - 30 天`；
2. 剩余若 > **10000** 条，从最旧开始删到 10000 条。
启动时与每分钟各跑一次巡检，修剪结果写日志。

### 6.3 内容
- 1-2000 字，`Array.from` 计长度（兼容 emoji）。
- 纯文本渲染，`textContent` 写入，不解析 HTML/Markdown → 天然防 XSS；`http(s)://` 自动识别为链接。
- 保留换行与连续空格（`white-space: pre-wrap`），长串自动折行。
- 限流：同一设备 10 秒内最多 10 条，超出 `429`。
- `clientMsgId` 去重（3 分钟内），网络重试不会产生重复消息。

## 7. HTTP 接口

统一 JSON，鉴权用请求头 `X-Session-Id`（登录/注册/健康检查除外）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/register` | 注册账号 |
| POST | `/api/login` | 登录，占一个在线位 |
| POST | `/api/logout` | 释放会话（支持 `?sid=` 供 sendBeacon 使用） |
| POST | `/api/heartbeat` | 心跳续期 |
| GET | `/api/me` | 校验会话、返回身份 |
| GET | `/api/messages?limit=3` | 首屏最近 N 条 |
| GET | `/api/messages?afterId=N&limit=50` | 增量拉取 |
| POST | `/api/messages` | 发消息 |
| POST | `/api/account` | 改用户名 / 密码（需当前密码） |
| GET | `/api/state` | 在线成员与游标 |
| GET | `/api/config` `/api/health` | 配置 / 健康检查 |

**错误格式**：`{ "error": { "code": "ROOM_FULL", "message": "当前在线已满（20/20），请稍后再试" } }`
错误码：`ROOM_FULL` / `INVALID_CREDENTIALS` / `INVALID_INPUT` / `USERNAME_TAKEN` / `RATE_LIMITED` / `SESSION_EXPIRED` / `ACCOUNT_LIMIT` / `NOT_FOUND`。

**轮询策略**：间隔 3s；无新消息时返回空数组（< 100 字节）；连续失败保持 3s 重试并把状态点置灰，收到 `401` 直接回登录页。

## 8. 数据结构

```js
// 消息
{
  id: 1287,                          // 自增，单调递增，作为游标
  deviceKey: "张明#Windows-PC",
  username: "张明",
  deviceName: "Windows-PC",
  displayName: "张明 · Windows-PC",
  content: "早上好……",
  clientMsgId: "5f1c…",
  createdAt: 1763000000000
}

// 会话（内存）
{
  sessionId: "s_9f2a…",
  deviceKey: "张明#Windows-PC",
  username, deviceName, displayName,
  lastSeen: 1763000000000,
  ip: "192.168.1.8"                  // 仅排障用，不下发前端
}
```

**存储**：`data/messages.json`（`{ nextId, messages: [] }`）写临时文件后 `rename` 原子替换，200ms 合并落盘；启动整体读入内存，查询走内存数组。1 万条量级内存 < 5MB。

## 10. 异常与边界

| 场景 | 处理 |
|---|---|
| 服务重启 | 内存会话清空，前端 `/api/me` 收到 `401` → 回登录页，消息不丢 |
| 在线已满 | 登录返回 `409`，登录卡内联红字提示 |
| 断网 | 状态点变灰「重连中」，恢复后按 `afterId` 补齐，不漏消息 |
| 游标失效（历史被清理） | 服务端返回 `reset:true` + 最新快照，前端整体替换 |
| 多标签页 | 共用同一会话；一个标签页退出，另一个下次请求收 `401` 后重新登录 |
| 修改账号 | 该账号全部会话失效，强制重新登录 |
| 超长消息 | 前端计数变红 + 禁用发送；服务端二次校验 |
